# 1.0.0 design foundations — P-1 / Y-1

This incremental PR keeps the application version at 0.5.1. It is not a
release candidate for 1.0.0. Pano and Yörünge workspaces and screen-specific
layouts follow in separate PRs; until then they use the existing Atlas
workspace with their own palettes and shared control appearances.

## Approved decisions

- Four design choices: Atlas Pro, Odak Akışı, Pano, Yörünge.
- Pano resolves to light; Yörünge resolves to dark. The colour selector is
  disabled and displays that effective mode. Stored `color_mode` is preserved,
  including `system`, and applies again when returning to Atlas/Odak.
- Search remains search even when an HTTP/HTTPS URL is pasted. No automatic
  New download dialog is added by the future Pano/Yörünge search controls.
- Actions absent from the supplied mockups use the locations proposed by
  the Pano/Yörünge screen documents, as approved by the user.
- JetBrains Mono is embedded unmodified under OFL 1.1, with no system install.
  See UPSTREAM-NOTICES.md and assets/fonts/JetBrainsMono-OFL.txt.

## Shared integration contract

`theme_catalog.theme_key(settings)` resolves a supported appearance;
`THEMES` contains the six supported appearances (four existing combinations,
plus `pano_light` and `yorunge_dark`). Migration/backup keep the independent
preference. Unsupported Pano-dark and Yörünge-light palette keys are rejected.

`palette()` supplies existing roles plus the design-specific roles from the
packages. Buttons, selections, inputs, switches, file tiles and progress bars
reuse their existing classes. `font`, `text_on`, `ellipsize` accept optional
`family='JetBrains Mono'` for measured mono text; their default remains Inter.
`text_px()` and all PIL drawing apply TEXT_SCALE once. No business logic is
placed in appearance helpers.

Claude-owned extension, music, statistics, page scanner, ui_dialog.py,
completion_dialog.py, database.py and video_downloader.py are untouched.

## Foundation-stage visual differences

- Main window layouts intentionally remain the Atlas workspace; P-2/Y-2
  implement their tile/telemetry layouts.
- Appearance cards use a two-column grid to keep their descriptions readable
  in the current settings shell. Screen-specific P-4/Y-4 layout follows.
- This PR provides the control palette, pill/square/chamfer appearances,
  mono button labels, square switch, tile outline and segmented progress.
  Dedicated gauges, full-window grid, tile shadows, menus/toasts, HUD and
  screen-specific layouts are subsequent work.
- Settings keeps its current reusable field/card shell. P08/F08 complete
  screenshot parity is not claimed by the foundation PR.
- Mockup fixture filenames, paths and transfer measurements are not copied
  into defaults or application data.

Native component previews cover six appearances. Alignment tests measure
shared baselines, text centring, form/action coordinates and footer gap;
reports reject missing appearances, invalid geometry and stale source hashes.
UI tests run only in temporary profiles and under the shared test lock.

Merge is the user's action. CI PR #14 restricts automatic release workflow
runs to main pushes changing app_version.py; manual workflow_dispatch remains.
This branch is rebased onto that change. Intermediate 1.0.0 PRs do not bump
the version and must not publish or replace 0.5.1. The existing release
duplicate-version guard remains in place. The final version bump and release
notes belong to the separate 1.0.0 release PR.
